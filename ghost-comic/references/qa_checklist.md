# 格子檢查表（給獨立檢查的 subagent）

你是另一個人。prompt 不是你寫的，圖也不是你挑的；你的工作是找出每張候選圖裡**畫錯的地方**，不是欣賞它。`manga.py review` 產生的 brief 列了每格的要求和每張候選的路徑。每張都開原圖看，不要只看縮圖或拼貼。

## 逐張檢查

1. **數人頭、數手、數腳。** 人數要跟 brief 寫的「剛好 N 人」一樣；brief 寫的是一段描述（「一群看不清的病人，不用數」）就照描述判。每個人兩隻手、兩隻腳；抱胸、拿東西、插口袋時特別數。上一本的學長雙手抱胸，身體兩側又各垂下一隻手，挑圖的人沒看到，擁有者看到了。
2. **同一個人不能出現兩次。** 角色卡上有兩個視角，模型常照抄成兩個人；路人裡也不能有長得像主角的人。
3. **每個角色的特徵都在。** 照 brief 的特徵逐項對：眼鏡、帽子、髮型、髮色、衣服上的條紋、鬍子。少一項就記下來。
4. **大小和位置合理。** 照 brief 的比例句：誰比誰高、鬼比誰小或比什麼高。也看位置：該坐著的有沒有坐著，有沒有人坐到桌上、站到不該站的地方。
5. **光線對。** 夜晚就是夜晚（背景平塗黑），白天就是白天（背景白）。同一段劇情的格子要一致。
6. **場景對。** brief 有寫場景格局的，家具、門、帳篷的位置和數量要對；從某個視角看不到的東西（從帳篷裡看出去看到帳篷）不能出現。
7. **沒有字、沒有陌生人、沒有多出來的東西。** 招牌、海報、螢幕上的字、亂碼；brief 沒寫的人；多一張椅子、多一頂帳篷。
8. **鬼守規矩。** 比活人小、臉大半在陰影裡，除非 brief 寫了別的。
9. **跟格子要的事情一致。** brief 的「畫面要的是」那句：動作、鏡位（特寫還是全身）、看向哪裡、表情（該哭的有沒有哭）。
10. **跟已選定的格子接得上。** brief 列了「要跟這些已選定的格子接得上」的話，開那些圖比對：同一件道具（顏色、門的數量、把手）、同一個人的髮型和衣服、同一個房間的家具。第三本的衫櫥在遠景是深色雙門，近景卻畫成白色三門，就是這一條。

## 判斷尺度

- **不合格**（讀者會看到、或這格的意思會錯）：
  - 人數、手腳的數量不對；同一個人出現兩次。
  - 少了讀者用來認人的特徵，例如眼鏡、帽子、髮型。
  - 光線狀態錯了，例如白天背景變黑。
  - 這格要的動作或表情沒有、或剛好相反：該哭沒哭、該坐卻站、該面向衫櫥卻背對。
  - 畫面裡有字。
  - 跟上面列的已選定格子接不上。
- **小毛病**（照樣判合格，行尾標「（小：…）」）：在漫畫格子的大小下看不出來、不影響讀者看懂的地方。例如一小塊糊掉的記號、少畫幾顆雀斑、手勢方向差一點、背景線條有點亂。
- 一格的候選全部不合格時，寫「最接近的是 pN_k」和它差在哪裡，重畫的人就知道從哪張的構圖出發。

## 回報格式

每張候選一行，照這個格式，不要多寫評論：

```
p22_1  不合格  多兩隻手（抱胸，身體兩側又各一隻）
p22_2  合格
p22_3  合格    （小：毛巾邊緣有點糊，不影響）
```

最後一行列出每格建議挑哪張（只從合格的裡面挑，都不合格就寫「重畫」並說要改什麼）：

```
建議：p22=2  p31=重畫（阿凱站著，要坐著；最接近的是 p31_2，只差在坐姿）
```

## 跨格檢查（`review --cast`）

brief 列的是**同一個角色**出現的每一格（已選定的），加上他的角色卡。逐格的檢查只看一格對不對；這一份要看的是這個人每一格都還是同一個人。每一格都開原圖，總覽圖只用來找哪幾格不一樣。

逐項比，先跟角色卡比，再跟其他格比：

1. **臉。** 臉型、眼睛大小、鼻子、皺紋、痣。一格的臉像換了一個人，就算表情對，也是不合格。
2. **頭髮。** 髮型、長短、髮色（黑、白、灰），每一格都一樣。
3. **衣服和配件。** 衣服的花紋、領子、帽子、眼鏡；手錶、鐲子、髮夾戴在哪一隻手、哪一邊。注意左右：`mirror` 翻過的格子在頁面上左右會反，但 brief 裡的是原圖。
4. **身材和比例。** 胖瘦、身高；跟同一格裡其他人的比例照 brief 的比例句。
5. **故事裡本來就會變的不算錯。** 「畫面要的是」寫了換衣服、回憶裡比較年輕、變成鬼之後臉色發灰，就照那句判；沒寫的差異就是畫錯。

回報格式：先一行一格，只列有問題的，最後一行總結：

```
p12  不合格  沒戴眼鏡；角色卡和其他格都有
p18  不合格  外套變成格子的，p17、p19 是素面
其他 9 格一致。
```

## 場景跨格檢查（`review --scene`）

brief 列的是**同一個場景**（同一個房間、同一個院子）選定的每一格，加上這個場景寫死的固定格局。逐格檢查只看一格對不對；這一份要看的是每一格都還是同一個地方，東西都在同一個位置。每一格都開原圖，總覽圖只用來找哪幾格不一樣。

逐項比，先跟固定格局比，再跟其他格比：

1. **門、窗在哪一面牆。** 窗戶的大小、扇數、窗簾的樣子；門在哪一邊、門口掛什麼。
2. **大件家具的位置和樣子。** 床靠哪面牆、床頭朝哪裡、有沒有床頭板和欄杆；櫃子、桌子是不是同一件（抽屜數、高矮、把手）。
3. **物件朝哪裡。** brief 寫了某個東西要朝向哪裡（相框對著窗戶、椅子背對門），就看畫面讀不讀得出那個方向。從鏡頭看得出朝向，才算對；只是「轉了一點」看不出來的，算不合格。
4. **鏡頭換了，格局不能換。** 從門口看、從床上看、從窗外看，同一扇窗、同一張床都要在說得通的位置。
5. **故事裡本來就會變的不算錯。** 白天晚上的光、窗簾拉開拉上、東西被拿走，「畫面要的是」寫了就照那句判。

回報格式跟跨格檢查一樣，一行一格，只列有問題的，最後一行總結：

```
p6   不合格  窗戶在左牆，固定格局是後牆正中
p30  不合格  床有床頭欄杆，其他格都是沒有欄杆的矮木板床
其他 8 格一致。
```

## 不要動的東西

只回報，不要改 `out/` 裡的任何檔案，也不要跑 `choose`。要放大、裁切或調亮暗部時可以寫小程式，但程式和輸出只放在 brief 指定的 work 資料夾（`out/review/work/<brief 名>/`）；不要寫到共用的暫存資料夾，上一位檢查員就蓋掉了別人的程式。
